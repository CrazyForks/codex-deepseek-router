# 2026-08-18 DSH alignment evaluation summary

## Scope

- One live eight-task A/B/C smoke batch (24 requests).
- One Flash-only tuning refinement batch (four requests, adapter v2).
- One final Flash SPEC structural verification (one request, adapter v5).
- Results contain automatic scores, public usage, latency and response hashes;
  provider response text and credentials are not stored.

The initial tuning text regressed the small valid-response sample and was not
retained. Pro accounted for seven of the batch's eight network failures; B and
C have identical Pro prompts, so their response differences are provider or
sampling noise rather than a Pro tuning change.

## Flash refinement

The shorter v2 tuning fixed the REACT honesty-constraint failure. Combining its
three non-SPEC Flash tasks with the final v5 SPEC check produced 3/4 automatic
passes, no network errors, 14,854 ms mean latency, 480 mean input tokens and
1,678 mean output tokens. The remaining `fast-callers` failure also occurred in
Current and Contract-only, so it is not a tuning regression.

The v5 Flash SPEC check passed with `escalate_to_pro=true` and all eight
Evidence Packet fields present. It used 535 input tokens, 3,053 output tokens
and 25,815 ms. This is a single structural check, not a stable performance
claim.

## Gate decision

The contracts, result schema and evaluation harness advance. Full repeated
performance claims do not. The live three-task Flash-to-Pro comparison was not
run after seven of twelve Pro smoke requests failed at the network layer. P2
near-field injection, mechanical closure, dynamic tool-surface work and
same-role fan-out remain disabled until reliable repeated evidence exists.
